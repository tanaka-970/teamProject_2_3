1. いまの Motion は After Effects 型で、既に完成している
-------------------------------------------------------------------------------
RePlayEngine/Motion/MotionAsset.h

    MotionBinding     component_index / property / relative_path で対象を指す
    MotionKeyframe    easing / MotionBezierHandles / easing_curve
    MotionWiggle      amplitude / frequency / seed / octaves
    MotionExpression  source（式）

つまり「PropertyRegistry のプロパティに時間でキーを打つ」仕組み。

足りないのは 3ds Max 側、つまり骨だけ。


2. 骨をプロパティとして出す案は却下した
-------------------------------------------------------------------------------
一度「骨を bones[LeftArm].rotation のような動的プロパティへ出せば、
既存の Motion がそのまま 3D アニメーションになる」と考えたが、
依頼者から渡された参考実装を読んで取り下げた。

参考: Downloads/ブレードクローラーcpp群/RigAnimationData.h

    RigAnimationTransform  scale / rotation(クォータニオン) / translation
    RigAnimationKey        time + transform
    RigAnimationTrack      bonePath + 補間 + keys
    ExternalAnimationClip  modelPath / skeletonHash / duration / frameRate / tracks

プロパティへ割ると負ける理由:

  - 回転がクォータニオン。オイラー角の float 3 本へ割ると補間でジンバルが出て、
    最短経路も取れない
  - skeletonHash が要る。骨構成の変わったクリップを弾くため。
    プロパティ名では表現できない
  - 骨は bonePath（階層のパス）で指す。名前だけでは足りない

結論: タイムライン・イージング・レイヤーの UI は共有し、データだけ 2 種類にする。


3. モデルへの埋め込み（依頼者の要望）
-------------------------------------------------------------------------------
参考実装は既に持っている。Scene/AnimationEditorSceneIO.cpp

    ExportCurrentClipToGlb(dest, replaceEditingEmbedded)
    ModelResource::SetGLBExportEnabled(true) -> ExportGLB()
    mEditingEmbeddedAnimation   埋め込み済みの何番目を編集中か

保存は 2 系統に分かれている。

    .animemama.json   作業中の外部クリップ（軽い）

このエンジンには ExportGLB 相当が無い。GLB は読む側しかない。
埋め込みは最後の工程になるが、データの形は最初からそれを見据えて決めること。
クォータニオン・bonePath・skeletonHash を持っていれば後から焼ける。

5. 踏んだ地雷
-------------------------------------------------------------------------------
アニメーション未設定だと keyframe が nullptr。
  骨の取得をアニメーション経路の内側に書くと一度も走らない。
  バインドポーズは offset_transform（逆バインド行列）の逆行列。

ポーズ適用時のパレットは、触っていない骨でちょうど単位行列になること。
  offset * posedGlobal がそれ。余計な行列を挟むとモデル全体が歪む。

Model Effect Stack の矩形はポーズを知らない。
  stack.scissor は GetSkinnedMeshLocalBounds から作られ、骨の姿勢を見ない。
  骨を伸ばして境界を超えると、超えた部分だけ合成されず白く残る。
  対策: ポーズが 1 つでもある間は scissor_enabled を落とす。
  ポーズが無いときの挙動は変わらない。

既存のギズモ（draw_object_transform_gizmo）は 326 行で
  複数選択・ピボット・スナップを抱えている。骨を通す改造は危険なので、
  骨用は別関数にした。投影だけは framework::project_world_to_screen で共有し、
  描画と当たり判定がズレないようにしてある。

エディタの新しい窓は DockBuilderDockWindow を足すだけでは docking されない。
  保存済みレイアウトが優先されるので、editor_layout_version を上げて
  作り直させる必要がある。上げないと窓が浮いて他のパネルに被る。
